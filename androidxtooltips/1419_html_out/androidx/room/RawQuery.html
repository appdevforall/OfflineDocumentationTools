If you know the query at compile time, you should always prefer Query since it validates the query at compile time and also generates more efficient code, since Room can compute the query result at compile time (e.g. it does not need to account for possibly missing columns in the result). On the other hand, @RawQuery serves as an escape hatch where you can build your own SQL query at runtime but still use Room to convert it into objects. @RawQuery methods must return a non-void type. If you want to execute a raw query that does not return any value, use androidx.room.RoomDatabase.query methods. @RawQuery methods can only be used for read queries. For write queries, use androidx.room.RoomDatabase.openHelper.
